Projects

GRC Automation Toolkit

Ten Python tools that automate compliance tasks I have done manually for years. Built independently, tested against synthetic data, all source public.

  • Access reconciliation — compares system accounts against an HR roster and flags access that should have been removed. Tested against a 505-record synthetic dataset with a known answer key; identified all 25 planted exceptions, 20 terminated users and 5 orphaned service accounts.
  • Control testing sample generator — reproducible random sampling with a fixed seed, so a reviewer can re-create and defend the exact selection.
  • Findings register analyzer — calculates finding age and groups by owner to show who is carrying the most and whose are oldest.
  • Vendor risk scorer — applies a weighted rubric to questionnaire responses and assigns a risk tier for TPRM triage.
  • Log analyzer — parses raw authentication logs and flags after-hours access, failed logins, and privileged activity.
  • Access expiration checker — flags overdue and due-soon access reviews, recertifications, and vendor assessments.
  • Findings summary — tallies a findings register by severity for an instant Critical/High/Medium/Low breakdown instead of counting by hand.
  • Control crosswalk mapper — maps NIST SP 800-53 controls to ISO 27001 and reports both coverage and gaps, so overlapping framework obligations can be tested once.
  • Control library — tracks a control inventory with owners and last-tested dates, and flags which controls are overdue for testing.
  • Findings deduplicator — normalizes finding descriptions and removes duplicates, which matters when registers get merged across sources or assessment cycles.

These are functional prototypes tested on synthetic data, not production systems. Source on GitHub

This Site — AWS Static Hosting

Deployed from a CloudFormation template: private S3 bucket, CloudFront distribution with Origin Access Control so nothing but CloudFront can read the bucket, HTTPS enforced. Infrastructure defined as code and reproducible.

I reviewed the template before running it and logged two gaps against my own site: encryption is not explicitly declared, and access logging is not enabled. Neither breaks anything — S3 encrypts by default — but a control that is not declared is a control an assessor cannot verify. Source on GitHub
